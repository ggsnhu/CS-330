# CS-330
Comp Graphic and Visualization

My approach to designing software has evolved over the course of my education. In the beginning, I would just immediately start coding whatever feature or basic aspect of the software I determined needed to exist. Now I know that the best approach is to analyze the requirements first and separate everything into modular goals so that each feature of the software can be completed in isolation without getting bogged down by big-picture thinking.

I relied heavily on experimentation and trial and error during the construction of my 3D scene because I had never worked with graphics in this form before. It took some getting used to how everything is set up in the code, but after some time, it became trivial to make small adjustments to the transforms of the shapes, as well as the lighting, color, and texture. In this project, iteration played a large role because I was constantly making changes and running the program to see results. By the time I got to the final project, I was pretty adept at making these changes. My approach during the early stages of the project was just to get all the basic shapes constructed, then go through and apply textures before finally working on the lighting.

Any new skill I learn is helpful whether I use it or not, because it aids in my understanding of how software is made, which informs my decision-making. I realize that I may not work with graphics daily in the future, but gaining this fundamental understanding of how these systems function has definitely given me a clearer view of the broader software landscape and will aid my decision-making.
